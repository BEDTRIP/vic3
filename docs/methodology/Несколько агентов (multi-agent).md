# Несколько агентов (multi-agent)

## Суть

Несколько сессий работают в одном проекте одновременно без живого оркестратора: работу режет подготовка, исполнителей
разводят [[Задача (issue)|задачи]] с заявкой, результат сводит [[Проверка (docs lint)|проверка]]. Главная сессия нужна, только когда
работу нельзя нарезать заранее.

## Правила

**Без оркестратора:**

- **Нарезка — заранее, с человеком:** этап делится на задачи с `touches` и `depends` — как подготовка задания
  агенту ([[Задание агенту (agent brief)]]).
- **Заявка** — агент берёт задачу коммитом её файла в общую ветку ([[Задача (issue)]]); двое одну не возьмут — второго не
  пустит отправка.
- **Своя рабочая копия и ветка у каждого агента** (в git — `git worktree`): чужих незакоммиченных файлов и чужого
  индекса рядом нет. В общую ветку попадает только прошедшее проверку документации и тесты проекта; сливает сам
  агент, когда ставит задаче `review`: перенос на свежую общую ветку, проверки, отправка; не сошлось — задача `blocked`
  с причиной. Приёмки слияние не ждёт — ветка, которая ждёт человека, расходится с остальными.
- **Одновременно идут задачи с непересекающимся `touches`.** Общий ресурс вне git — сервер, видеокарта, тестовый
  стенд, выкладка — тоже в `touches`: у него один хозяин в каждый момент.
- **Чужую область не правят** — заводят [[Баг (bug)|баг]] или задачу её владельцу. Смежные задачи встречаются на
  [[Понятие (explanation)|понятии]]: его «Как должно быть» — договор между ними; меняется договор — сначала понятие, потом код.
- **Общих файлов, которые пишут все, нет:** ход — в файле задачи, таблицы — виды по шапкам, «Состояние» плана
  и карту понятий в одно время правит один — уборка. Постоянный номер (ADR, ключ задачи) занимают коммитом файла-заготовки.
- **Коммит — явными путями, только свои файлы:** в рабочей копии может лежать чужая незаконченная работа.
- **Ветки.** План, этапы и задачи ведутся в рабочей ветке — там, где идёт работа; на ветке прода они —
  состояние выложенного и приходят туда с релизом. Общие файлы при слиянии веток сводит один.
- **Вопрос человеку** — в [[Очередь человека (review queue)|его очередь]], задача — `blocked`, агент берёт следующую.
- **Уборка** — раз в день, одна сессия или скрипт: снять протухшие заявки, найти неслитые ветки упавших сессий
  (задаче — `blocked` с причиной), переписать «Состояние» [[План проекта (roadmap)|плана]]. Сливает не она — агент при `review`.

**С главной сессией** — когда задачу нельзя нарезать заранее (исследование) или части надо сплавить в один текст
(разбор литературы). Главная раздаёт части и сводит итог:

- у каждого агента — свои файлы; общий файл правит только главная, агент присылает для него готовые строки;
- задание называет, чего не трогать и как проверить себя в конце;
- результат агент пишет в файлы, а не только в ответ: главная может упасть, и отчёт пропадёт с ней; что сделано —
  восстанавливают по файлам;
- в отчёте — что прочитано полностью, что частично, что не открылось, что агент принял сам ([[Как писать (style guide)]]);
- агент без источника не правит по памяти: не открылось — оставить как есть и перечислить.

Ночью, когда человека нет, главная сессия — дирижёр: работу не режет и не сводит, только раздаёт готовые задачи
плана по аккаунтам и проверяет итог ([[Ночная работа (multi-agent night run)]]).

**Предел — не число агентов, а внимание человека:** агентов добавляют, пока [[Очередь человека (review queue)|его очередь]] и
приёмка не растут.

## Почему

Оркестратор делает три вещи — режет работу, разводит исполнителей, сводит результат; каждую держит правило с
исполнителем: нарезку — файлы задач, развод — отказ отправки и `touches`, сведение — проверка перед слиянием. Живая
главная сессия — единая точка отказа: падает она — теряются отчёты и порядок.
