# Перевод проекта на методологию (migration guide)

Делается отдельной задачей, не попутно с фичей. Каждый пункт — отдельный коммит; [[Проверка (docs lint)]] — после каждого.

1. **Метод в проект** — папка метода целиком в `docs/methodology/`, отдельным коммитом. Прежние правила
   документации проекта (папка или файл вроде `documentation.md`) — удалить, ссылки на них — на заметки метода. Где
   метод не подходит проекту — правка самого метода, с выбором человека, для всех проектов ([[README|методология]]).
2. **Метод агенту — с начала сессии.** Хук начала сессии агента (в Claude Code — `SessionStart`) кладёт в контекст
   [[README|карту метода]]; в точке входа агента (`CLAUDE.md`, `AGENTS.md`) первым блоком — «работа
   по методу; перед задачей, багом, ADR, уроком — его заметка». Иначе агент принимает метод за предмет, а не за
   инструкцию, и ему приходится напоминать.
3. **Список понятий и карта (MOC)** — из существующих документов, кода и схемы данных. Показать человеку до того, как
   писать заметки: что считать понятием и как группировать — его выбор ([[Понятие (explanation)]], [[Понятие (explanation)#Карта|карта]]).
4. **Заметки понятий** — «Суть» и «Как должно быть» из существующих документов, «Где» — сверкой с кодом. Расхождения
   документов с кодом — отдельным списком человеку, не исправлять молча.
5. **Процедуры (how-to)** — оставить в них только «как сделать»: команды, пути, порядок, грабли. Описание «что это» —
   в понятия, в процедуре ссылка; описание кода — в документы кода рядом с ним ([[Процедура и справочник (how-to, reference)]],
   [[Документ кода (module README)]]).
6. **План, этапы, задачи** — папка `план/`: из реестров задач и статусов — открытое в этапы (epic) и задачи (issue)
   с ключами областей, цели и состояние — в `план/README.md`, закрытое — в историю ([[План проекта (roadmap)]], [[Этап (epic)]],
   [[Задача (issue)]]).
7. **ADR**: каждое прежнее решение — файлом `ADR-NNNN`; решения, на которые уже ссылаются документы и код, — с их
   номерами; источник каждого (документ, коммит) — в «Контексте». Был реестр одной таблицей — разложить по файлам,
   номера сохранить ([[Решение (ADR)]]).
8. **Баги**: известные дефекты из планов, списков ошибок, «Открыто» и TODO в коде — задачами `kind: bug`, оттуда —
   ссылками ([[Баг (bug)]]); номера, которые уже есть, — в ключи. Пути к документам в комментариях кода — на ключ или на
   документ кода рядом ([[Документ кода (module README)]]); перенесли документы кода — дымовой прогон программы. Опыт — грабли
   процедур, ошибки агента, память агента — уроками в `уроки/` ([[Урок (lessons learned)]]).
9. **Шапки** всем документам, скриптом где можно; упоминания документов, ADR и задач в тексте — ссылками
   ([[Шапка документа (frontmatter)]], [[Ссылки (wikilinks)]]).
10. **История**: старые тематические архивы не переписывать, только шапка; дальше — по правилам ([[История (archive)]]).
11. **Скрипт проверки** — под раскладку проекта, в CI ([[Скрипт проверки (linter)]]).

**Definition of Done**: старых папок документации нет — всё разложено по видам; скрипт проверки проходит без находок
и стоит в CI; в коде нет путей к `docs/` — только ключи, номера ADR и документы кода рядом; хук начала сессии и точка
входа агента ведут в метод и новую раскладку; что поменяли в методе — в «Итоге» этапа.

## Обновление метода

Метод поменялся — проект берёт его целиком, отдельной задачей:

1. Папку `docs/methodology/` заменить действующим методом одним коммитом — без выборочного переноса заметок: метод
   в проекте всегда цельный.
2. Что поменялось — дифф этого коммита. По каждому изменённому правилу — привести документы проекта: шапки, раскладку,
   скрипт проверки; переименованная или слитая заметка — поправить ссылки на неё. Остальное не трогать.
3. [[Проверка (docs lint)]] — 0 находок; что пришлось поменять в проекте — в ходе задачи.

Правило, которое проекту не подходит, на обновлении не откатывают у себя: правят сам метод, с выбором человека, и
обновление приходит во все проекты.
