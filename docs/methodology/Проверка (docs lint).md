# Проверка (docs lint)

## Суть

После правки документов — скрипт проекта, одна команда, код выхода 1 при находках (её можно поставить в хук или CI).
Он держит правила метода, которые человек и агент забывают: битые ссылки, упоминания текстом, понятия вне карты.
Как написать — [[Скрипт проверки (linter)]].

## Правила

Скрипт проверяет:

- каждая ссылка ведёт на существующий документ, каждое понятие есть на карте, у каждого — «Суть»;
- каждый якорь (`#Раздел`, `#^метка`) ведёт на существующий раздел или метку;
- нет неоднозначных ссылок — `[[Имя]]` при двух документах с этим именем;
- ссылка не разорвана переносом строки; на документы нет ссылок Markdown — только ссылки Obsidian ([[Ссылки (wikilinks)]]);
  ссылка Markdown без схемы (`[текст](путь)`) ведёт на существующий файл — иначе в графе фантомный узел;
- упоминаний документов текстом нет (ADR по номеру, задача по ключу, этап по номеру, путь к документу, имя понятия, раздел рядом со
  ссылкой); скрипт умеет сам сделать их ссылками; имя у двух документов — списком;
- у каждого документа есть `type`, `description`, `project` и ключи своего вида; значения `type` и `status` — из
  списков ([[Шапка документа (frontmatter)]]);
- пути из `paths` существуют; код, которого нет ни в одном `paths`, — списком;
- документы, у которых код из `paths` менялся после коммита из `verified`, — списком «возможно, устарели»;
- у понятия `status` совпадает с тем, пуст ли раздел «Открыто»;
- у закрытого бага есть `verified_by` (`verified`), причина (`invalid`), `duplicate_of` (`duplicate`) или ADR в `adr`
  (`wontfix`); у `fixed` — `fixed_in`; у открытого пути из `paths` существуют; `severity` из списка;
- в коде: ключ задачи или номер ADR из комментария есть среди документов (открытых или в истории), путь к документу
  из комментария существует и ведёт в документ кода ([[Документ кода (module README)]]);
- у [[Задача (issue)|задачи]]: имя начинается с ключа своей `component`; `in-progress` — есть `assignee` и `claimed`; `blocked` — есть `question`;
  `review` — есть `question`; `done` — есть `verified_by`; пути из `touches` существуют; `depends` ведёт на задачи; закрытая лежит в истории, открытая — нет;
  заявка старше срока без коммитов — списком «протухла»; две `in-progress` с пересекающимся `touches` — списком;
- рабочие файлы не разрослись: файл этапа и файл задачи больше порога проекта — списком; «Состояние» плана старше
  срока при свежих коммитах — списком; в строке таблицы столько же ячеек, сколько в её заголовке;
- у [[Решение (ADR)|ADR]]: `accepted` — есть `date` и `deciders`; `superseded` — есть `superseded_by`;
- документы-сироты — без единой входящей ссылки, от карты до них не дойти, — списком (справочно: история бывает
  сиротой законно, её не считают).

История проверяется мягче — только ссылки и якоря ([[История (archive)]]).

**У правила — исполнитель.** Правило, нарушение которого дорого, держит не абзац текста, а то, что сработает само:
проверка в CI, которая роняет сборку, скрипт, который сравнит с прошлым разом и напишет человеку, файл рядом с тем,
что он охраняет. Правило только текстом — пожелание: его забудут.

Нет скрипта — хотя бы поиск старого имени после переезда файла.
