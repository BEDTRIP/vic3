# Проект из нескольких репо (polyrepo)

## Суть

Проект бывает из нескольких репозиториев: продукт, инструменты, внешние источники. Общее у них — план, этапы и
задачи, сквозные понятия и ADR, окружение, уроки, метод — живёт в **узле**: своём репозитории, рабочая копия которого —
папка над клонами остальных; она же хранилище Obsidian. Остальные репо — подпапками в `.gitignore` узла.

## Правила

- **Узел — обычный проект по методу:** `docs/` со входом, `план/` с этапами и задачами, `решения/`, сквозные
  `понятия/`, `devices/`, `уроки/`, `история/`, `methodology/` ([[Где лежит (docs layout)]]). Вход агента — правила
  узла; у каждого репо — свои.
- **Документ — в репо того, что он описывает:** понятия, документы кода, ADR — в репо, чьё понятие они описывают или
  воплощают; что касается нескольких репо — в узле. Так правило «документ в одном коммите с кодом»
  ([[Как писать (style guide)]]) держится внутри репо.
- **План, этапы и задачи — только в узле**, для всех репо (баги тоже — это задачи): этап часто трогает несколько репо,
  а сессия читает одно место. Область задачи (`component`, код в ключе) — обычно репо или его подсистема; `touches` —
  пути с папкой репо. Код — коммитом в своём репо, файл задачи — коммитом узла; в ходе задачи — репо и хеш
  (`форк a1b2c3d`). Сообщения коммитов в обоих — с ключом задачи.
- `project` — один на узел и все репо ([[Шапка документа (frontmatter)]]).
- **Ключи и номера уникальны по всему проекту:** у ADR — один счёт `ADR-NNNN` на все репо, у задач — ключ области: на
  них ссылаются из любого репо и из кода. Номер ADR занимают коммитом заготовки в том репо, где он ляжет; что номер
  свободен во всех репо, смотрит [[Проверка (docs lint)|проверка]] узла.
- **Ссылки между репо** — обычные ссылки Obsidian: хранилище — папка узла, все репо в нём; неоднозначное имя — хвостом
  пути с папкой репо ([[Ссылки (wikilinks)]]). GitHub эти ссылки не открывает — их читают в Obsidian или агентом.
- **Проверка** ([[Проверка (docs lint)]]) — один скрипт на проект, раскладка каждого репо — в его настройке. CI репо
  проверяет свои ссылки; ссылки между репо, номера, `paths` и `verified` на чужой репо — проверка узла, ей нужны клоны
  соседей рядом.
- **Язык.** Репо — публичный продукт на другом языке (инструмент для всех): его документы — на языке продукта, а
  план, задачи и ADR о нём — в узле на языке проекта.
- Узлу, как любому репо, нужен remote: облачные сессии берут репо с GitHub.
- Внешние источники, которые проект не правит (игра, чужие моды, фреймворки), — репо снимков и граф документов вне
  снимков ([[Внешний источник (vendoring)]]).

## Почему

План в каждом репо — несколько «состояний»: сквозному этапу нет дома, и что делается в проекте, не видно ни из одного
места. Все документы в узле — документ уходит из коммита кода, который описывает, и расходится с ним. Узел — папка над
клонами, потому что хранилище Obsidian должно видеть все репо, иначе ссылки между ними не работают. Счёт номеров с 1 в
каждом репо даёт два ADR-0012 — ссылка из кода перестаёт значить одно.
