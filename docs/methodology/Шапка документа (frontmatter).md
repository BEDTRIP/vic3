# Шапка документа (frontmatter)

## Суть

Шапка (YAML frontmatter, в Obsidian — свойства) у каждого документа — как у заметки в базе знаний: по ней человек фильтрует и строит таблицы в
Obsidian, агент выбирает, что открыть, [[Проверка (docs lint)]] — что устарело. Как у научной статьи: `description` — аннотация,
`tags` — ключевые слова.

## Правила

Ключи — английские; значения `type` и `status` — из списков ниже, стандартные (трекеры, ADR, Diátaxis): агент знает их
заранее; остальное — на языке проекта.

**У каждого документа:**

| ключ | что |
| --- | --- |
| `type` | вид документа — [[Один вопрос — одно место (single source of truth)]] |
| `description` | одна строка: о чём документ и когда его открывать; агент читает шапки, а не файлы целиком |
| `project` | имя проекта — одно на все его репозитории; так видно сразу всё по проекту или по нескольким; у этого метода — `methodology` |
| `tags` | ключевые слова — темы, которые проходят через разные документы; не повторяют `type` и папку |

**По виду документа:**

| `type` | ключи |
| --- | --- |
| `explanation` | `aliases` (синонимы, имя в коде), `status`: `open` / `done` (пусто ли «Открыто»), `adr`; `uses`, `replaces` — на какие заметки [[Внешний источник (vendoring)\|источника]] опирается и что подменяет; у заметки самого источника — `source`, без `status` |
| `epic` | `status`: `todo` / `in-progress` / `on-hold` / `done`, `date` (начат), `touches` (область этапа — папки кода и ресурсы, по умолчанию для его задач), `start` (у отложенного — дата, раньше которой не браться) |
| `issue` | `kind`: `task` / `bug`, `component` (область, её код — в ключе имени), `epic`, `date` (заведена), `status` — у `task`: `todo` / `in-progress` / `blocked` / `review` / `done` / `wontdo`, у `bug`: `unconfirmed` / `confirmed` / `in-progress` / `blocked` / `fixed` / `verified` / `wontfix` / `invalid` / `duplicate`; `assignee` и `claimed` (кто взял и когда, у `in-progress`), `touches` (папки кода и общие ресурсы, которые меняет), `depends` (задачи, без которых не начать), `start` (дата, раньше которой не браться — у задачи на потом), `question` (что спрошено у человека: у `blocked` — чего ждёт, у `review` — что посмотреть и где), `answer` (ответ человека; пишет он сам), `verified_by` (чем принята или проверена, у `done` и `verified`); у бага ещё `severity`, `paths`, `fixed_in` (коммит, у `fixed`), `duplicate_of`, `adr` (каким выбором оставлен, у `wontfix`) |
| `adr` | `status`: `accepted` / `superseded` / `deprecated`, `date` (когда решили), `deciders` (человек или агент по его слову), `superseded_by`, `epic` |
| `lesson` | `date` (записан), `applies` (где ещё пригодится: ОС, инструмент, вид работы), `epic`, `issues`, `adr` (откуда урок) |
| `history` | `date` (закрыт), `kind`: `epic` / `snapshot` / `journal` / `audit` / `research`, `epic` |
| `code`, `how-to` | `paths`, `devices`, `verified`, `adr`, `tests` — по необходимости |
| `reference` | `generated` — если собирает скрипт; `devices` |
| `roadmap`, `moc`, `entry` | только общие ключи |

**Служебные — ставит агент, когда они что-то дают:**

| ключ | что |
| --- | --- |
| `paths` | какие файлы и папки кода описывает документ (маски); по ним видно, какие документы задевает правка кода, и какой код не описан нигде |
| `verified` | дата и коммит, на котором документ сверен с кодом; код из `paths` менялся позже — документ, возможно, устарел |
| `generated` | чем собирается файл; руками не править — перезапустить |
| `audience` | кому заметка: `agent` — только агенту (генерат для работы, выписки, промежуточное), человеку её не показывают; нет ключа — человеку; см. [[#Кому заметка\|«Кому заметка»]] ниже |
| `tests` | какие тесты проверяют то, что описано в «Как должно быть» |
| `devices` | к каким устройствам и серверам относится документ — ссылками на их понятия ([[Окружение (infrastructure)]]) |

- Агент может завести и другой ключ, если по нему что-то делается; ключ, по которому ничего не делается, не нужен.
- **Даты — в `date`, не в имени файла.** Имя — о чём документ; хронология — сортировкой по `date`.
- Ссылки в шапке — в кавычках ([[Ссылки (wikilinks)]]).

## Кому заметка

Не всё в вольте проекта — для человека: генерат, который агент собирает себе для работы (тысячи заметок по исходникам,
выписки, промежуточные разборы), нужен агенту и забивает человеку граф, поиск и списки.

- Такой заметке — `audience: agent`. Ставит тот, кто её создаёт: генератор — в каждую, агент — в свою рабочую.
  `generated` — о другом (как собирается): справочник, собранный скриптом, может быть и человеку — тогда без `audience`.
- Агентские заметки — по возможности в своей папке (папка генерата, `_agent/`): папку человек скрывает целиком.
- Человеку их скрывают виды Obsidian: граф — фильтр `-[audience:agent]`, поиск — тот же, Bases — условие
  `audience != "agent"`; большую папку генерата — ещё и «Исключённые файлы» (поиск, граф, быстрый переход).
- **В тексте** документа для человека на агентскую заметку не ссылаются: по ссылке в тексте кликают, а там — не для
  него; нужное переносят словами или путём. **В шапке** — можно и нужно: ключи-связи (`uses`, `replaces`, `adr`
  и подобные) — для агента и [[Проверка (docs lint)|проверки]], по ним у агентской заметки видно обратными ссылками, кто на неё
  опирается. Из агентской в человеческую — как угодно.
- [[Проверка (docs lint)]] по агентским заметкам — только шапка и битые ссылки; сироты и «нет описания понятия» — не дефект.
