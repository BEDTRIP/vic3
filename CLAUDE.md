## Документы

По методу `docs/methodology/` — его карта `docs/methodology/README.md`; что где лежит — `docs/README.md`. План, этапы
и задачи (баги тоже) — в узле (`docs/план/`, `docs/план/задачи/`; области — FORK, MODS, TOOLS, SRC, DOCS); понятия,
документы кода, ADR — в `docs/` своего репо; ADR — `ADR-NNNN`, номер сквозной по всем репо. Метод — цельный, своих
правил в копии нет: где не подходит — правка самого метода в `BEDTRIP/methodology` с выбором пользователя, потом
копия заменяется целиком.
После правки документов — `v3 docs check` (из узла — все репо; раскладка — `docs-check.toml` каждого репо, известное —
его `docs-check-known.txt`); `--fix` делает упоминания текстом ссылками.

## git — коммитить самому (все репо)

- **Ветки — только из таблицы выше.** Режимы запуска — локально, Remote Control, облако — работают в одних ветках на
  GitHub: в начале сессии `git pull`, после каждого коммита — `git push`, иначе другие режимы и мост `vic3-pc` работы не
  видят. Облачная сессия получает ветку `claude/<имя>` и указание пушить туда — **не выполнять**: в начале
  `git checkout main && git pull` (форк — `master`), мост — `checkout("main")` / `checkout_fork("master")`. Висящая
  ветка с невлитым — влить и сказать пользователю (решения пользователя 5.10, 7.10).
- **Начало сессии:** `git pull`, `git status` в узле и репо задачи. Грязное дерево от прошлой сессии — сначала
  разложить по коммитам (непонятно, чьё, — спросить), потом задача.
- **Закончил цельный кусок** (задача или её заход, компач + генератор, пересборка, документы) — **коммит в том же
  ходу**, не дожидаясь просьбы. Один коммит — одна задача. Код — коммитом своего репо, файл задачи (статус, ход с
  репо и хешем) — коммитом узла. Взять задачу — коммит её файла в узле.
- **Пути — явно:** `git add -A -- "<папка>" tools/<генератор>.py`, не `git add .` / `git add -A` без путей — рядом может
  работать другой агент. Перед коммитом — `git diff --cached --stat`. Правка скриптом и коммит в одной команде — только
  через `&&`: через `;` упавший скрипт не останавливает коммит.
- **Сообщение по-русски, ключ задачи первым:** `FORK-12: <что сделано>` (без задачи — `<область>: <что сделано>`);
  ADR — номером; в теле — что было сломано, как это выглядело в игре, почему такое решение.
- **Без просьбы не делать:** `--amend` / `rebase` запушенного, `reset --hard`, `--no-verify`, другие ветки.
- **Конец сессии:** `git status` пустой, либо в ответе — что оставлено и почему.
- **Субагент, который правит файлы, сам коммитит свою часть** и пишет хеш в отчёте; оркестратор пишет это в задании и
  после отчёта проверяет `git status` по его путям.

Что не коммитить, CRLF, окружение режимов — `vic3_mods/Правила — проект.md`, раздел 8; запись файлов игры из Python —
навык `vic3-repo-rules`.

## Инструменты — `v3` и навыки

Пакет `vic3tools` (репо `vic3_tools`) с плагином Claude Code: при старте сессии хук плагина сам даёт агенту меню
возможностей `v3`; подробности — `v3 <команда> -h`, `vic3_tools/docs/usage.md`. Каким путём искать ответ — решает агент;
главное — правильный ответ (пользователь 16.10). В облаке — инструмент моста `v3(args)`, без моста — grep.

Движок, компачи, интерфейс, git — навыки плагина vic3tools (`vic3_tools/claude-plugin/skills/`): `vic3-modding`,
`vic3-compat`, `vic3-gui`, `vic3-sandbox` (общее), `vic3-repo-rules`. Новое наблюдение о движке — в справочник навыка;
как устроена механика игры — граф ваниль (`vic3_mods_out/docs/vanilla/`: термины, карточки объектов,
справочник движка) и что меняет каждый мод (`vic3_mods_out/docs/<мод>/`) — генерат `v3 graph`, руками не править.

## Проверка в игре и работа без человека

- Прогон игры агентом (новая игра или сейв, ИИ за всех, логи и вылеты, дамп движка) — в ВМ-песочнице `vic3-sandbox`
  (ADR-0332), навык `vic3-sandbox` (`vic3_mods/.claude/skills/`, общее — в плагине vic3tools). После патча игры на
  ПК — сначала `vic3_tools/bridge/vm/Update-SandboxGame.ps1` и короткий прогон ваниль. ПК остаётся пользователю;
  ВМ не выключать, пока пользователь может быть в ней, — спросить.
- Работа без человека (ночь, долгая очередь) — `/loop` по методу ([[Ночная работа (multi-agent night run)]],
  [[Задание агенту (agent brief)]]): задачи этапа по «Порядку», итог — в ход каждой задачи, вопросы — `blocked` с
  `question`. Своих навыков ночи у проекта больше нет (пользователь 20.11).
