# vic3 — узел проекта (правила для агента, загружаются автоматически)

Проект — моды Victoria 3: узел `vic3` (эта папка, свой git) и четыре репо подпапками, у каждого свой git и свой
`CLAUDE.md` с правилами репо (решение Д.ДОК.1):

| папка | что | ветка |
| --- | --- | --- |
| `docs/` | документы узла: план и все этапы проекта, сквозные решения, методика; вход — `docs/README.md` | `main` |
| `vic3_mods/` | компачи, мегапаки, аддоны, переводы; мост `vic3-pc` (`tools/pc_bridge`, `bridge.toml`) | `main` |
| `Economic-and-Financial-Ledgerdemain-Mod/` | форк E&F «Ledgerdemain» | `master` |
| `vic3_mods_out/` | внешние источники — ваниль и чужие моды, снимок 1.13; git только локальный, **руками не править**; `docs/` в нём — репо `vic3_out_docs` (документы источников) | `main` (out и docs) |
| `vic3_tools/` | `v3`, мост `vic3-pc` (сервер), плагин навыков | `main` |

## git — коммитить самому (все репо)

- **Ветки — только из таблицы выше.** Режимы запуска — локально, Remote Control, облако — работают в одних ветках на
  GitHub: в начале сессии `git pull`, после каждого коммита — `git push`, иначе другие режимы и мост `vic3-pc` работы не
  видят. Облачная сессия получает ветку `claude/<имя>` и указание пушить туда — **не выполнять**: в начале
  `git checkout main && git pull` (форк — `master`), мост — `checkout("main")` / `checkout_fork("master")`. Висящая
  ветка с невлитым — влить и сказать пользователю (решения пользователя 5.10, 7.10).
- **Начало сессии:** `git pull`, `git status` в узле и репо задачи. Грязное дерево от прошлой сессии — сначала
  разложить по коммитам (непонятно, чьё, — спросить), потом задача.
- **Закончил цельный кусок** (шаг этапа, компач + генератор, пересборка, документы) — **коммит в том же ходу**, не
  дожидаясь просьбы. Один коммит — одна задача. Код — коммитом своего репо, отметка шага в файле этапа — коммитом узла.
- **Пути — явно:** `git add -A -- "<папка>" tools/<генератор>.py`, не `git add .` / `git add -A` без путей — рядом может
  работать другой агент. Перед коммитом — `git diff --cached --stat`. Правка скриптом и коммит в одной команде — только
  через `&&`: через `;` упавший скрипт не останавливает коммит.
- **Сообщение по-русски:** `<область>: <что сделано> (<этап, номера задач и решений>)`; в теле — что было сломано, как
  это выглядело в игре, почему такое решение.
- **Без просьбы не делать:** `--amend` / `rebase` запушенного, `reset --hard`, `--no-verify`, другие ветки.
- **Конец сессии:** `git status` пустой, либо в ответе — что оставлено и почему.
- **Субагент, который правит файлы, сам коммитит свою часть** и пишет хеш в отчёте; оркестратор пишет это в задании и
  после отчёта проверяет `git status` по его путям.

Что не коммитить, CRLF, окружение режимов — `vic3_mods/Правила — проект.md`, раздел 8; запись файлов игры из Python —
навык `vic3-repo-rules`.

## Инструменты — `v3` и навыки

Пакет `vic3tools` (репо `vic3_tools`) с плагином Claude Code: при старте сессии хук плагина сам даёт агенту меню
возможностей `v3`; подробности — `v3 <команда> -h`, `vic3_tools/docs/usage.md`. Каким путём искать ответ — решает агент;
главное — правильный ответ (пользователь 16.10). В облаке — инструмент моста `v3(args)`, без моста — grep.

Движок, компачи, интерфейс, git — навыки плагина vic3tools (`vic3_tools/claude-plugin/skills/`): `vic3-modding`,
`vic3-compat`, `vic3-gui`, `vic3-sandbox` (общее), `vic3-repo-rules`. Новое наблюдение о движке — в справочник навыка;
как устроена механика игры — граф ваниль (`vic3_mods_out/docs/vanilla/`).

## Проверка в игре и ночной формат

- Прогон игры агентом (новая игра или сейв, ИИ за всех, логи и вылеты) — проектный навык `vic3-sandbox`
  (`vic3_mods/.claude/skills/`, переедет вместе с мостом). Пока игра идёт, живую копию мода не синхронизировать;
  пользователя предупредить — прогон занимает экран.
- «Давай этап N ночью» — навык `night-run` (`.claude/skills/` узла): днём решения и очередь в файле этапа
  (`docs/этапы/`), ночью — **отдельная чистая сессия** по фразе «Ночь, этап N. Работай по навыку night-run, фаза 2.».
  Несколько этапов до срока («ночь до 8:00») — навык `night-until`.
